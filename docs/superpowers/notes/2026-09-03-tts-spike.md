## Update 2026-09-05 — torchcodec failure confirmed NOT Python-version-specific

Built a clean `D:\tts-venv312` (Python 3.12.3, no `--system-site-packages`), installed `torch==2.14.0+cpu` + `f5-tts` fresh. `torchcodec 0.16.0+cpu` **imports fine** but still fails at decode time with the identical error as the 3.14 venv:

```
OSError: Could not load this library: ...\torchcodec\libtorchcodec_core6.dll
FileNotFoundError: Could not find module '...\libtorchcodec_core5.dll' (or one of its dependencies)
```
(tries core6/core5/core4, all fail the same way — `f5-tts_infer-cli` ran ~44s of setup then aborted at audio I/O, same as the earlier 3.14 attempt)

**Root cause is now clear: it's not the Python version.** `torchcodec`'s bundled loader needs a real *shared* FFmpeg build (`avutil-*.dll`, `avcodec-*.dll`, etc.) discoverable on `PATH`. This machine only has the static, no-shared-libs `ffmpeg.exe` from `video/node_modules/ffmpeg-static/`.

## Update 2026-09-05 — fixed: FFmpeg shared build unblocks local TTS

Downloaded `ffmpeg-n8.1-latest-win64-gpl-shared-8.1.zip` from **BtbN/FFmpeg-Builds** (GitHub releases — a Windows FFmpeg build source ffmpeg.org itself links to; used instead of the originally-suggested gyan.dev only because it ships as `.zip`, trivial to extract with `Expand-Archive`), extracted to `D:\ffmpeg-shared\...\bin`, prepended that dir to `PATH`. Re-ran the identical `f5-tts_infer-cli` command from `D:\tts-venv312` (Python 3.12.3) — **it worked**, no torchcodec error.

- Engine: **F5-TTS-Vietnamese**, checkpoint `yukiakai/F5-TTS-Vietnamese` → `model_85044.safetensors` (1.35 GB, license **CC-BY-NC-4.0**, author's own description: "test version with pretty bad quality").
- Env: `D:\tts-venv312` (Python 3.12.3, `torch==2.14.0+cpu`, `f5-tts` from PyPI) + `D:\ffmpeg-shared\ffmpeg-n8.1-latest-win64-gpl-shared-8.1\bin` on `PATH`.
- Command:
  ```
  python -m f5_tts.infer.infer_cli -m F5TTS_v1_Base \
    -p D:\d\tts-models\f5-vi\model_85044.safetensors -v D:\d\tts-models\f5-vi\vocab.txt \
    -r assets\voice\sample.wav -s "<sample.txt content>" -t "<~40s gen text>" \
    -o out -w f5_vi.wav --nfe_step 32
  ```
- Result: **21.6 s** audio generated in **1736.7 s (~28.9 min) wall**, RTF ≈ **80×** — but the run log shows batch 1/2 alone took 25:37 of the 28:18 total, i.e. almost all of it was one-time cold-start (HF Hub download of the Vocos vocoder + model load onto CPU), not steady-state synthesis; a warm second call should be far faster. Not yet measured warm-RTF or done a second run to confirm.
- Output sent to user for a listen: `scratchpad/f5out/f5_vi.wav` (not committed — personal voice data).
- **Not yet judged:** subjective similarity to `sample.wav` — waiting on user's listen.

**Net effect:** the local blocker is resolved (Python 3.12 venv + FFmpeg shared DLLs). Remaining open questions before picking `video.tts_provider`: (1) does the user judge this checkpoint's quality/similarity acceptable, given the author calls it a "bad quality test version" and a much larger `hynt/F5-TTS-Vietnamese-ViVoice` checkpoint (5.4 GB) exists; (2) CC-BY-NC-4.0 blocks commercial use on a monetized channel — GPT-SoVITS (MIT) remains the preferred engine to actually validate for production, this F5-TTS run was a fastest-path proof that local CPU voice-cloning is achievable at all on this machine; (3) real (warm) RTF still needs a second timed run to separate cold-start from synthesis cost.
